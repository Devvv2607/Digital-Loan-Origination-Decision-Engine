# Simulation report: 500 synthetic applications

> Demo prototype. Simulated integrations and synthetic data. Not affiliated with any bank or lender.
> Generated by `scripts/run_simulation.py` from a real run against the API. Do not edit by hand.

**What this shows, and what it doesn't.** A 100% match on these defined synthetic scenarios shows that the engine, state machine and API behave as specified. It does **not** show production readiness or real-world credit-risk performance: there are no repayment outcomes in this simulation, and the personas were designed to sit clearly inside or outside each rule.

## How often each rule and check fired

A rule *fires* when it returns DECLINE, REFER or INFO (R6 counter-offer) on an engine decision. F1 fires at the PAN step, where it blocks the application before any decision.

| F1 | Duplicate PAN | 20 | – | – | – | – |
| F2 | Application velocity | 8 | 0 | 8 | 0 | 10 |
| F3 | Identity mismatch | 25 | 0 | 25 | 0 | 10 |
| F4 | Income inconsistency | 25 | 0 | 25 | 0 | 30 |

*Not evaluated:* the engine stops before credit rules when the bureau is unavailable after retries (D-08), so every rule is skipped for those applications. F4 is also not evaluated when the applicant declined AA consent, because there is no verified income to compare.

## R2 seeding check (credit-risk cut-off scenario)

R2 was calibrated so that 88.2% of the mock bureau's population would pass. On this test set, 390 of 430 scored applicants (90.7%) scored ≥ 631, and the overall engine approval rate was 38.7%. Both differ from 88.2% because the test set deliberately over-represents borderline, thin-file and failing applicants, and approval also depends on R1, R3–R6 and the fraud checks. This calibration is illustrative and does not establish equivalent risk; the reference project's 5.9% payment-difficulty rate is not reproduced or claimed.

## Metric definitions

- **Match:** Actual outcome equals the expected outcome AND the set of reason codes equals the expected set.
- **Match rate:** Matching applications ÷ 500.
- **Outcome:** Engine decision (APPROVED / REFERRED / DECLINED), or BLOCKED_AT_PAN (F1 409 at PAN verification), or KYC_PENDING (e-KYC timed out after retries).
- **Rule fired:** The rule returned DECLINE, REFER or INFO in the decision's rule results; F1 counted from PAN-step blocks.
- **Confusion matrix:** Rows: expected outcome from the persona definition. Columns: actual outcome from the API.
- **Reason codes complete:** As defined in docs/RULES.md §5.
- **Legal transitions:** Every STATE_CHANGE event starts where the previous one ended and is in the allowed-transition table (docs/STATE_MACHINE.md §3).
- **Funnel, conversion, drop-off, instant-decision, referral and fraud-flag rates, TAT:** As defined in docs/PRD.md §7, read from /metrics/funnel and /metrics/tat.
- **R2 pass share:** Scored applicants (bureau returned a score) with score ≥ the R2 approve threshold ÷ scored applicants.
